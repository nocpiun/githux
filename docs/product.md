# 产品约定

更新：2026-10-22。以下是已确认基线的共享摘要，具体未定项在末尾。概念图用于讨论布局，不替代真实 Ely 窗口的视觉验收。

## 目标与技术方向

Githux 通过紧凑、清晰、顺畅的桌面界面访问 GitHub。Rust + GPUI + Ely；首版只做 Windows，macOS/Linux 产品支持延后，已有跨平台编译 CI 保留。早期无框架 TypeScript 方案已被后续选型替代。现阶段聚焦远程 GitHub 内容，本地 Git 暂存、提交、复杂合并和 IDE 能力未纳入范围。

可保存多个账户，同一时刻仅一个活动账户；离线可查看已缓存内容，联网后刷新。首次工作流验证曾只限制一个实现 Agent；该限制已解除，不能由此推导产品或长期流程必须串行。

## 登录与未来写能力

负责人于 2026-10-22 确认 PAT 为首版正式登录方式。用户自行创建并输入 token，应用直接访问 GitHub，凭据进入系统凭据设施；本项目不建设认证后端或托管 `client_secret`。

为覆盖保留的 Notifications 和跨组织仓库读取，首版接入 **Classic PAT**（细粒度 PAT 目前不支持 Notifications，依据见 [能力表](github-api-capabilities.md#认证方式矩阵)）。登录后验证账户身份、实际授权及受限功能，过期或撤销时引导替换 PAT；组织策略/SSO 仍可能限制访问，不能保证用户网页中可见的所有资源都对当前 token 可见。

当前先实现阅读链路，架构须为未来远程写操作保留权限检查、提交结果及缓存失效边界，见 [架构约定](architecture.md#认证与外部边界)。`repo` scope 本身包含私有仓库的读写权限；不把当前阅读 UI 描述成只读 token，也不为了未来操作预先要求所有管理权限。H7 的具体动作仍待逐项确定，预留能力不等于现在实现全部写功能。

## 外壳与导航

- 自定义标题栏：首版 Windows 左上 Githux 字样、右侧三个窗口按钮，验证拖动、缩放、贴靠等系统交互。顶栏下方不画分隔边框。macOS 左侧按钮后接 Githux 的既有设计留待后续平台支持。
- Windows 三个窗口按钮使用 Windows App SDK 的系统绘制 Tall 模式：品牌/搜索区保留 32px 内容行，上下各留 8px，典型顶栏高 48px；Githux 使用 Ely 的 Md 字号（默认 14px），搜索框自身高 28px、在内容行内垂直居中；实际行高读取系统 Height 并按窗口 DPI 换算，island 从该行下缘开始。按钮区域不加 padding。SDK 初始化失败回退到原有标准高度 DWM 适配；DWM 也不可用或无原生 HWND 的测试平台保留自绘回退（直角单框/重叠框）。macOS/Linux 不安装此适配。Tall 按钮的背景、交互、高度与对齐，以及最终品牌字号/搜索框高度均已获负责人真实预览验收，证据见 [Tall 标题栏记录](devlog/2026-10-23-tall-caption.md)，原有 DWM 验收见 [原生按钮记录](devlog/2026-10-23-native-caption.md)。
- 侧边栏直接从顶部导航开始，没有额外 Logo/品牌块。上方 Home、Settings，中间仓库列表，底部账户信息与快捷入口。
- 仓库显示 namespace 头像和 `namespace/repo`。全部仓库通过分页加载到有界区域，只有仓库 group 独立滚动，上方与底部保持固定；不能让侧栏无限增长。范围确定为 `GET /user/repos` 在当前活动账户、token 与组织授权下返回的集合（owner、collaborator、organization_member），不限定单个组织；排序与局部筛选待定。
- 底部点击头像/名称进入 Profile；展开时下方横向四等分图标入口为 Notifications、Issues、PRs、New，不放主题切换。侧栏支持受限 resize 和 56px 图标栏收起，收起后四入口合为“...”菜单；New 在创建范围未批准前继续禁用。仓库列表与固定 footer 之间有细分割线；账号区只有头像/名字/@ID 打开 Profile，展开时右侧另有占位 emoji 状态按钮（点击不导航、无写状态功能），收起时隐藏并把状态并入头像 tooltip。仓库/页面/palette 的滚轮使用共享平滑适配，触控板像素滚动直接响应。账号区独立间隔、客户区外留白、行外活动线与交互契约见 [侧栏布局](sidebar-layout.md)，最终视觉与滚动手感等待负责人真实窗口验收。
- 右上角固定搜索入口，点击打开 command palette；具体搜索范围与快捷键待定。R1 首份外壳交付只提供本地导航命令（各页与当前仓库列表），不调用 GitHub，也不据此确定未来全局搜索范围。
- 侧栏以外的页面主区域采用 island，与窗口边缘留微小距离，内外圆角协调。不是所有子面板都变成浮动卡片；精确间距、圆角和最大化行为待真实窗口确认。
- island 顶部为应用级会话标签（tab strip），可同时保留多个仓库、Issue/PR、个人主页等；它和页面内的横向内容 Tabs 是两层不同导航，不共用状态。页面内容内的大标题保留，不再显示重复页面名称的占位标题条，也不保留其高度。Profile 首版只实现 Overview。
- 基础标签规则（负责人 2026-10-23 确认）：点击侧边栏仓库、底部入口或通过 command palette 选择页面时，统一执行“打开或激活”——同一资源已打开则切换到该标签，否则新建。Home、Settings 及当前全局占位页（Notifications、Issues、Pull requests）按路由单例，仓库按 `owner/repo` 单例；GitHub 名称大小写不敏感，同一资源的别名不生成重复会话。不支持同资源重复标签。启动仍只有 Home，不恢复上次会话。
- 账户与标签（负责人 2026-10-28 确认）：每个账户拥有自己的打开标签集合，切换回某账户即恢复该账户自己的标签、顺序与活动标签；全局式标签（如 Settings）同样属于当前活动账户的 workspace。账户身份是 host + 稳定账户 ID，不是登录文本或 PAT，因此账户 A 与 B 拥有同一仓库或相同本地标签编号时，标签与异步身份都不会互相串。这是进程内内存状态：重启仍从 Home 开始，不扩展 workspace 持久化。
- 关闭非活动标签不切换当前标签；关闭活动标签切换到左邻标签，没有左邻则右邻；关闭最后一个标签后新建 Home 标签。
- 标签可鼠标打开/切换/关闭，键盘可到达（Tab 焦点与 Enter/Space），`Ctrl+W` 关闭当前标签，`Ctrl+Tab` / `Shift+Ctrl+Tab` 切换标签；这些组合键不与输入法候选确认（Enter/Esc/方向键）或文本输入争用。
- 每个标签拥有独立的页面滚动位置、焦点与仓库会话状态（分支/选中文件，真实读取在 R3 接入）；关闭标签释放这些状态，标签 ID 不复用。
- 标签数量不设上限（负责人 2026-10-25 反馈推翻了此前的 `MAX_OPEN_TABS = 8` 预览边界）：只要有资源可打开就新建标签，不压缩、不换行、不撑宽窗口、不拒绝新的页面。标签保持可读的固定宽度，超出可用宽度后由**横向滚动**承载，这一项取代此前 H6 对水平滚动的排除。
- 溢出时提供可拖动的水平滚动条；未溢出时不显示。滚动条是细线（约 3 logical px）、半透明的中性色，不画粗大的实心轨道；仅当指针在标签条区域时才出现，进入/离开有约 140ms 的淡入淡出，反向操作从当前透明度继续而不是跳到端点，拖动期间保持可见并在释放后回到 hover 状态，完全隐藏时不保留可点击的透明轨道，也不因透明度改变而重排或改变滚动位置。
- `Shift`+垂直滚轮、设备原生水平滚轮与触控板横向手势都只改变标签条的横向偏移，且不对系统已转换的 delta 二次转换；滚动只影响标签条，不影响页面与侧栏。
- 新建、显式激活、键盘切换或 Tab 聚焦到可视区外的标签时，把该标签尽量完整滚入可视区；普通重绘不重复抢回滚动位置，用户手动滚动仍可浏览其他标签；关闭标签后收窄偏移，避免末尾留下大片空白。
- 标签支持水平拖拽排序（负责人 2026-10-25 新增，取代此前 H6 对重排的排除）：按稳定标签 ID 移动会话顺序，不关闭、不重建、不换 ID，页面滚动/焦点/仓库会话状态与资源身份随原标签；松开后只调整一次顺序。拖到横向可视区边缘时有界自动滚动，使未显示的目标也能到达。取消、失焦或无效投放保持原顺序与当前标签，不跨窗口搬运。排序后 `Ctrl+Tab` 与关闭邻居按新的视觉顺序。固定标签、拖出新窗口、导航历史与重启恢复仍不做。
- 标签图标与标题之间保留适当间距（约 7 logical px），图标、标题与关闭按钮三个槽位的间距不同步放大，标题仍以省略号截断并保留完整名称。
- 每个标签的关闭按钮仅在该标签 hover 或处于活动状态时出现，即时显示/隐藏、无渐变动画；槽位始终保留宽度，所以显示与否不移动标题或其他标签。隐藏时不可点击、不留下不可见的键盘焦点目标；键盘聚焦不算第三种常显条件。`Ctrl+W` 与中键关闭始终可用。
- 标签条最右侧有一个固定的工具栏，不参与横向滚动、不挤出可视区；本轮只放一个禁用状态的刷新图标入口（tooltip 为 Refresh），不接任何刷新逻辑、请求或导航。
- 标签条内边距与 island 到窗口边缘的间距一致（约 7 logical px），上方与左侧相同；不计 island 的 1px 边框，滚动条带固定保留，所以滚动条出现/消失不移动标签。标签内容区域与 island 外框之间保持清晰边界。
- 鼠标中键在标签任意区域（图标、标题、空白、关闭按钮）只关闭该标签一次：不先激活非活动标签，不重复执行关闭，不触发滚动或其他点击动作。关闭语义与左键关闭按钮、`Ctrl+W` 一致。左键激活与键盘 Enter/Space 行为不变。
- 标签只用中性色表达状态：不显示彩色（含 focus 蓝色）描边，hover/active/按下也不出现；键盘焦点用中性文字色变化表达，不把非活动但聚焦的标签画成活动状态。
- H6 其余进阶交互（专门的溢出菜单、固定标签、拖出新窗口、前进/后退历史、重启恢复、重复资源标签扩展）仍不在本轮范围。

### Home 与 Feed 的数据范围

左栏通过 GitHub API 获取参与关系和条目更新，不以本地打开历史替代。候选查询是 `involves:当前用户名` 与条目更新时间排序；是否设时间窗口、是否额外包含仅被请求评审等关系，在 Home 实现任务中明确。标题不改为“最近打开”或“参与的讨论”，也不把“有更新”自动定义成“未读”。

右栏采用 Events API 的 `GET /users/{username}/received_events` 展示因关注用户、订阅仓库而收到的事件。负责人接受该来源的延迟；接口最多提供最近 30 天内的 300 条事件，可能延迟 30 秒至 6 小时，不承诺与 github.com 首页逐条一致。刷新遵守服务端限制；展示名称为 Feed，不要求每张卡片标注“API 事件流”。来源边界见 [Events 文档](https://docs.github.com/en/rest/activity/events#list-events-received-by-the-authenticated-user)。

## 视觉、字体与原生体验

配色、控件及状态画风沿用 Ely 原型；概念图不引入新主题。使用统一 token，信息密度靠组织和行高，不能一直缩小字体。

UI 默认 **Noto Sans**，代码默认 **Google Sans Code**。建议随包固定字体发行版及许可证；中文/其他语言、Emoji 回退和静态/可变字重仍需实测，不把默认字体选择误认为已解决所有字符覆盖。不要手工按字符猜字宽，测量、选区和绘制应使用一致的布局结果。

首版真实窗口需要验证：Windows 多 DPI 和跨屏、缩放、文本混排、中文 IME 预编辑与候选确认、焦点和键盘操作、选取复制、长列表滚动、窗口状态变化、island 裁切和浮层。macOS/Linux 原生验收延后；截图不能证明帧率、内存或输入行为。
