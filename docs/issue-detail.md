# Issue detail offline reading

The official `Route::Issue` opens `IssueDetailPage` and reads the Issue body and ordinary comments through `IssueDetailSession`. The page first loads the saved body and comments together from the application cache. Revalidation uses the active account’s fixed credential and starts the comment collection again at page one. The same loading and retry controls remain available for accounts without a usable cache.

The route index is scoped to the saved account partition and the normalized owner, repository name, Issue number and API representation. It points to a snapshot gated by a numeric repository ID confirmed through GitHub repository metadata. Index entries carry only the binding. Earlier unscoped Issue snapshots are ignored. A replacement credential needs fresh repository access proof before storing a snapshot for a quarantined repository. The cached view also carries a repository authorization stamp so revocation clears the body and comments, including on a visible page. The account lifecycle controls credential rejection and account switches. [Account lifecycle](cache-account-lifecycle.md)

The cache retains a contiguous prefix of previously loaded comment pages. It keeps up to ten pages and caps the serialized body-and-comments snapshot at 8 MiB, subject to the cache store’s own capacity. Only user-requested continuation pages can extend the saved collection. Each successful first page starts a new collection, and later pages must match that collection and the next page number. Unread pages and replay limits leave the list partial. The live **Load more comments** action uses the cursor returned by the latest successful online page.

While a refresh runs, the page keeps authorized content visible. A transient failure with saved content shows **Cached** and a retry. A retry hides the badge for the section being refreshed. Denial, missing resources and repository invalidation clear the previous reading. A `no-store` reply, including a failed reply, removes the affected durable snapshot. Successful online reads can still be displayed when persistence is unavailable. [Cache strategy](cache-strategy.md)
