# UI 字体实际命中排查与字重/tooltip 修复

- 日期：2026-10-29；任务 ID：ui-fonts；执行者：基层 Agent。
- PR：[#49](https://github.com/nocpiun/githux/pull/49)。状态：目标已改为 `feature/shell-pages`（stacked on #42），保留 `pending` 等负责人原生验收，不合并。原 main 上的通过是历史事实，不当作新组合已通过；组合验证以实时 `origin/feature/shell-pages` 为基线。

## 目标

核查正式 Shell 是否真的应用 Noto Sans，保留 Google Sans Code；不只检查常量字符串。

## 诊断结论（先证伪）

在本机 Windows（144 DPI，`target/debug/examples/*` 原生窗口，非测试平台）用 GPUI 文本系统导出实际 shaping 结果：

- **400 字重确实命中 Noto Sans**：`Home` 的 glyph id `[43, 82, 80, 72]`、14px 行宽 `39.83px`，与仓库 `NotoSans-Regular.ttf` 的 cmap/`hmtx` 逐项一致（Noto 的 `H/o/m/e` advance 之和 2845/1000 * 14）。系统里另一个字宽同为 `39.83` 的 `Sans Serif Collection`，其 `H/o/m/e/g` 轮廓与 Noto 逐点相同，不作为第二来源。中文串 `中文回退` 的 glyph `[1048,1926,1435,2846]` 与 `Microsoft YaHei UI` 一致，说明 CJK 走系统 fallback，而不是 Noto Sans（Noto Sans 无 CJK）。
- **500/600 之前没有得到 Noto 的真实字重**：仓库只打包了 Regular。字重 500 的行宽与 400 完全相同（`39.83`），600 变成 `40.950005`，而 700 与 600 相同；这来自 DirectWrite 的替代/合成面，不是 Noto Medium/SemiBold。因此“常量写了 Noto Sans、普通文字看起来正常”与“粗体/标签看起来不像 Noto”可以同时成立。
- **tooltip 读取的是 `.SystemUIFont`，不是主题字体**：在同一窗口内把所有可见祖先设为 Noto Sans，构建 tip 时 `window.text_style()` 仍是 `family=".SystemUIFont"`（同时 `theme.font_family == "Noto Sans"`），字形为 `[58,85,85,82,90,79,86,3,...]`。原因在 GPUI：tooltip 由 `prepaint_tooltip` 作为独立 root 布局/绘制，不继承挂载元素的 text style 栈；Ely 的 `Tooltip::text` 自身不设字体。这解释了侧栏、标签、按钮与仓库提示文字不像 UI 字体。

## 改动与决定

- `src/platform/fonts.rs`：从同一 Noto Sans v2.015 官方归档加入 `NotoSans-Medium.ttf` 与 `NotoSans-SemiBold.ttf` 并注册。选择静态字面而不是可变字体，是因为现有资源与许可按静态面记录，且 GPUI/DirectWrite 按 weight 选面；这补的是真实 Medium/SemiBold，不是把 600 映射到 400。
- `assets/fonts/noto-sans/*`：新增两个官方文件；归档 SHA-256 `0c34df07…` 本轮重新下载核验，与既有 Regular 的来源一致。未引入整套字体包、未升级 Ely/GPUI、未改 `Cargo.lock`。Bold（700）仍未打包，当前 Shell 也不请求 700。
- `src/ui/tooltip.rs`（新）：`ui_tooltip` / `ui_tooltip_content` 在 tip 自己的 root 上设置主题 UI family。GPUI 没有集中设置“窗口默认文本字体”的公开入口（`TextStyle` 默认 `.SystemUIFont`，只有 `with_text_style` 的绘制栈），所以只能在 tip 内容上补；这是最小可行修复，并把原因写进模块文档。
- 侧栏、标签、Home/Feed、Profile、仓库视图改用该 helper；Home/标签工具栏的 Ely `IconButton::tooltip` 不能从外部改内容，把提示挂到与按钮同尺寸的外层容器上，保留原命中区域与 `tab-refresh` / `*-refresh-slot` 选择器，避免同时挂两层 tip。
- `Google Sans Code` 未改：仍是单一可变直立文件，`wght` 轴覆盖代码文字所需字重；源码/Markdown 代码仍显式使用 `mono_family`。

## 2026-10-30：负责人中文验收返工

此前结论仅证明英文 Noto Sans 和系统 CJK fallback。负责人明确要求中文为应用提供的 Noto Sans SC，因此旧的“中文正常”截图与系统 YaHei 命中不能作为新要求通过证据。

实际检查 GPUI 0.3.10 Windows `direct_write.rs::generate_font_fallbacks`：它从 `system_font_collection.GetFontSet()` 查询 family，并用 `AddMapping(..., None, ...)` 建立映射；没有把自定义内存字体集合传入。因此仅注册 SC 并加 `FontFallbacks` 仍可能依赖用户系统安装。

采用 OFL 衍生私有字族 `Githux UI`：全部 2,965 个 Noto Sans 映射优先保留，补入 SC 的 30,361 个映射。四个权重 400/500/600/700 分别实例化官方 SC `2.004-H2`，与官方 Noto Sans v2.015 对应静态面组合。新主字族名用于区分衍生文件与上游，实际英文/中文轮廓不变；不把 Latin 换为 SC 的 Latin。Google Sans Code 原资源不动。四份资源共 43,707,220 B，来源、输出哈希和许可见 assets/fonts/README.md；CI artifact 增加 SC 的 OFL。

`scripts/build-ui-fonts.py`（fontTools 4.61.1，开发资源生成工具，无 Rust 新依赖）校验官方源 SHA，生成后逐一核对所有映射的轮廓坐标、轮廓终点、flags 和 advance。重复执行四份输出哈希一致。保留 GSUB/GPOS/水平 hinting，移除不适用的垂直/变量 BASE/STAT；新字面的垂直度量覆盖两种来源的 extents，防止中文标题被裁掉，实际混排与布局须看原生帧。

新增 `examples/fonts.rs` 复用产品 Shell、Accounts、page host、repository/Markdown reader，只有临时数据库、内存 synthetic 凭据和 transport 为 fixture；不访问真实账户/网络。含负责人样本“Minecraft 服务器管理面板”“简介”“功能特性”“菜单栏金额”“额度显示”“中文”，README 普通/粗体/标题和账户 UI/tooltip 同时覆盖。此入口只用于开发验收，不进入正常启动路径。
