# 2026-10-28 page-data

## 交付

- 新增 `src/data/page_reads.rs` 与 `PageReadSession`，把 Home/Feed、Profile 基本资料/Pinned/Contribution Calendar、Releases/Latest/Contributors/Languages 接入既有账户授权路径。每次返回 `Scoped<T>` 与原领域错误；Home/Feed login 来自捕获的活动账户，Profile target 与授权账户分离。
- `RepoService::read_authenticated` 与 `RepositorySession::read` 做了最小 data-module 可见性/泛型错误扩展，未复制凭据、semaphore、取消或 stale 逻辑，既有公开 Repository API 签名未变。`RepositoryReadContext` 额外捕获同一活动账户快照的 login，仍不保存 PAT。
- Feed/latest/languages 是无条件在线读取，不发送 validator；无 validator 的 Feed 304 明确成为 `HomeError::InvalidResponse`，不发布 NotModified/空列表。ETag/poll 与 extras metadata 仍随成功领域模型保留。
- 新增 Profile README helper，在一个授权固定 session 中完成 canonical public 同名仓库发现、default branch 固定 commit、README 发现、blob/content 准备。区分 Prepared/Missing/Unavailable/NotEligible；404 和发现失败不冒充确认缺失，private/internal 不候选。Share-to-profile 历史标记不可由 API 观察，已记录在主题文档。
- 新主题文档 `docs/page-data-service.md` 是三个 UI owner 的接口交接。未接 UI、缓存、存储、轮询、请求合并或图片加载，未宣称页面真实数据集成完成。

## 边界

没有真实 GitHub/PAT 联调或 GUI 验收，因为本任务只有数据层。低层接收期 bounded transport、真实 TLS/SSO/权限行为继续沿用各自文档的验证边界。当前不是 UI view model，也不做 all-or-nothing 聚合；后续 host adapter 必须在成功和错误发布前调用同一 RepoService 的 `is_current`，再检查页面请求代次。
