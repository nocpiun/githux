# 开发日志

每个有实质交付的任务一份 `YYYY-MM-DD-<task-id>.md`，日期使用 Asia/Shanghai。实现 Agent 维护自己任务的文件，修复轮次继续更新它，避免所有 Agent 争写单一总日志。无需为每个提交、轮询或聊天单独记录，也无需每次更新此索引。

按以下内容写短而可恢复的记录：

```markdown
# 任务标题

- 日期、任务 ID、执行者；PR/Issue 链接有了再补，没有则注明。
- 目标与状态：提案 / 实现中 / 待审查 / 待裁决 / 已完成（注明完成指什么）。

## 改动与决定
触发条件、结果行为、必要取舍；链接到主要维护的设计文档。

## 验证
实际命令、结果、对应提交或未提交工作区；明确未运行/未覆盖部分。

## 后续
剩余问题、需裁决事项、恢复工作所需的信息。
```

日志不是架构的主要维护位置，也不是实时监控表。当前真实 PR 状态、review 与 CI 到 GitHub 核验，不能仅凭旧日志认定通过。提交中的文档不要求记录自身 SHA；最终验证证据放 PR，避免为了补自身 SHA 无休止地产生新提交。

不得存凭据、完整本机会话、个人环境配置和原始大段终端输出。可重用的经验进入 [LESSONS](../../LESSONS.md)；长期事实回写所属主题。
