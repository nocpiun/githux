任务：修复用户问题 1、2、8：紧凑 owner/repo 元信息、文本边界链接（避免链接空白区触发 hover/tooltip/click）、以及平衡的 Issue/PR 行与元信息排版。
分支：`fix/ui-row-links`，base：`0c619070be103048f9aa033f2f57520372cbebb2`，Milestone：#1 (First Release)，pending 标签。

## 问题分析与根因

1. **用户问题 1 (owner/repo 间距过大)**：
   - 在 `src/ui/work_item_row.rs` 中，元信息行是 `metadata = div().flex().items_center().gap_2()...`。在 Split 模式下，`action_link(owner)`、斜杠分隔符 `div().child("/")` 和 `action_link(name)` 都是 metadata 顶层 flex 容器的直接子元素。
   - `gap_2`（8px）施加在 owner、`/` 和 repo 之间，导致 `#594 opanel-mc / opanel` 显得松散分离。
   - 修复：将 owner、`/` 和 repo 组合在紧凑的非交互式内联容器中（`gap_0p5`，即 2px），斜杠紧贴两侧文本，同时保持 `#number` 在最前且垂直居中对齐。

2. **用户问题 2 (repo 链接空白区误触发 hover/tooltip/click)**：
   - 原先在 `action_link` 中，当 `flex: true` 时，直接给交互链接元素 `element = element.flex_1()`。
   - 由于 repo 链接是元信息行上唯一 `flex_1` 的元素，链接本身的 Hit Target（包围盒）被拉伸到占据所有剩余空白宽度，一直延伸到右侧的 state 和 relative time 之前。
   - 鼠标悬停或点击 repo 文本右侧的空白区域时，会触发 repo 链接的下划线、tooltip 和点击跳转。
   - 修复：让交互式链接元素 `element` 保持文本自身边界大小（tight hit target），外层包裹非交互式的 `div().flex_1().min_w_0().overflow_hidden()` 容器来吸收剩余伸缩宽度。点击或悬停文本右侧空白区域不再触发链接行为。
   - 同步审计 Feed 对应行链接：`src/ui/home/rows.rs` 中的 `repository_links` 同样收敛至紧凑的 `gap_0p5()` 间距，且不干扰外层卡片整体选择。

3. **用户问题 8 (平衡行间距与选中底色对齐)**：
   - 保持 72px 共享行高 (`WORK_ITEM_ROW_HEIGHT = 72.0`)，内容居中 `justify_center()`，标题行与元信息行上下余量完全对称（差 ≤1px），外层卡片与条目选择底色边界精确匹配。
   - 在宽屏和窄屏截断、中文/英文混合等不同元数据场景下，排版紧凑且无溢出。

## 改动范围

- `src/ui/work_item_row.rs`：
  - `action_link`：移除交互元素本身的 `flex_1`，改为通过外部非交互 wrapper `div().flex_1().min_w_0().overflow_hidden().child(element)` 吸收伸缩空间。
  - `Split` 仓库链接：将 owner、斜杠和 repo 包装在带有 `gap_0p5()` 的容器中，消除宽大的 `gap_2` 间隙。
- `src/ui/home/rows.rs`：
  - `repository_links`：使用紧凑的 `gap_0p5()` 间距展示 owner / repo。
- `src/ui/home/tests.rs`：
  - 更新断言：验证 repo link 边界不再延伸至 relative time 之前。
  - 新增 `clicking_blank_space_after_repository_does_not_trigger_navigation`：测试点击 repo 链接右侧空白区不会触发导航，点击文本正常触发，同时覆盖 Feed 仓库链接。
  - 新增 `work_item_metadata_supports_compact_display_and_chinese_english_truncation`：验证中英文混合及窄视口截断下元信息紧凑且对齐。
