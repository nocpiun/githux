# PR 标签与规模门槛

任务：pr-gates。负责人要求主 Agent 实施，交付后保留 PR 等待人工验收，不合并。

## 行为

新增 `.github/workflows/pr.yml`，workflow/job 均名 `PR`，读取 GitHub 当前 PR 标签及总新增/删除行数。只有没有 `blocked` 且两个计数分别 <=20,000 才通过。标签增删、PR 更新/重开/换基线等事件触发，按 PR 并发取消旧运行。只读 API，无 checkout，无 PR 内容插入脚本。读取失败和过时 head/base 不通过。

审查 skill 的共享 `inspectHead` 在开始、收集完证据、重审前检查 `blocked`，返回现有 `merge_blocked` / 15 并保留具体阻塞原因；即使 `mergeable_state=clean`、CI/review 通过或没有 `--wait-ci` 也不能通过。`pending` 是 Agent 添加的人工验收标记，`blocked` 由负责人管理。规则的唯一主维护位置为 [Agent 工作流](../agent-workflow.md#pr-标签与规模门槛)。

## 验证

- 用 GitHub API mock 执行工作流中实际的 JavaScript，覆盖20,000/20,001边界、分别计数、大小写blocked、pending、实时标签替代旧事件、元数据缺失/API失败及过时head/base。
- 审查回归覆盖初始blocked、检查中新增blocked、移除后重查、标签字段缺失、自动重审前新增blocked和既有审查/CI流程。
- 本机 Windows / Node 24：`node --test .github/scripts/pr-policy.test.mjs .github/scripts/ci-scope.test.mjs .agents/skills/githux-pr-review/scripts/wait-review.test.mjs .agents/skills/githux-agent-dispatch/scripts/dispatch.test.mjs`，85 项全部通过；`git diff --check` 通过。
- 只读实测负责人已标记 blocked 的 PR27：新审查脚本在首读返回 `merge_blocked` / `blocked_label`，真实退出码 15，没有等待 CI、触发重审或修改标签。其他 PR 的状态未更改。
- GitHub 上新 `PR` 检查及当前 head 的 CI/review 结果在 PR 交接记录；离线测试不宣称服务器 required check 已配置。负责人自行在后台把 `PR` 设置为 required check，本任务不修改仓库保护。本任务 PR 添加 pending，等待负责人验收，不合并。
